# Plant Viewer: implementation brief

This is the working brief for the iOS side of Plant Viewer. It carries the parts of the
spec ("Plant Viewer: GLB to USDZ Spec", Sep 29 2026) that the app code needs, the decisions
made since the spec was written, and API facts checked against Apple's documentation on
2026-09-29. Where this brief and the spec disagree, this brief wins.

## Decisions since the spec

| Topic | Spec said | Now |
|---|---|---|
| Converter | Reality Converter (Mac GUI) | `scripts/convert_plant.py`, a scripted wrapper around `usdzconvert` (the engine Reality Converter used), through a Python 3 port and Pixar's `usd-core`. Apple pulled Reality Converter after WWDC25; its download URL now redirects to the Reality Composer Pro page. |
| Visual check | Reality Converter preview | The app itself, in the iOS Simulator, then on a real iPhone. Same checklist. |
| Host app | Top of Grove's Tree detail screen | This repo is the app. It opens on the plant catalog grid. No Tree detail screen. Target name `Grove`. |
| Devices | Open question | iPhone only for v1 (`TARGETED_DEVICE_FAMILY = 1`). |
| Info card | Open question | Shows `displayName`, `category` and `heightMeters` from the manifest. |
| Double-sided leaves | Not covered | RealityKit ignores USD's `doubleSided` flag, so leaf backs vanish when orbiting. The app turns off face culling on plant materials at load time (see Material fix-up). |

## Toolchain

- Xcode 26 or 27. Deployment target iOS 18.0.
- XcodeGen (`brew install xcodegen`). The Xcode project is generated from `project.yml` and
  is not committed. Run `xcodegen` after every pull.
- Any iPhone simulator. In the simulator, drag to orbit; hold Option and drag to pinch.

## Repo layout

```
project.yml                     # XcodeGen spec (local session creates this)
App/
  Sources/
    GroveApp.swift
    PlantViewer/                # the feature
  Resources/
    Plants/                     # plants.json, <id>.usdz, <id>-thumb.png; copied to bundle root
    Lighting/Studio.skybox/     # folder reference (XcodeGen type: folder), one equirect .hdr/.exr
  Tests/                        # unit tests (GroveTests)
  UITests/                      # UI tests (GroveUITests)
Assets/Plants/                  # not shipped: source GLBs, settings JSON, LICENSE-RECORD.md
scripts/                        # Python tooling (asset checks, GLB inspector, converter)
docs/
```

`App/Resources/Plants/` must be a normal group so each file lands at the bundle root, since
`Entity(named:in:)` looks up files by bare name. `plants.json` starts as `[]`. A placeholder
plant, `placeholder-a-01`, will arrive from the cloud session so the app has something to load
before real FABOTANIC plants exist. It is a stem with alpha-cutout leaf cards, generated by
script, with no license strings attached.

## Components (from the spec)

| Type | Role |
|---|---|
| `Plant` | `Codable` struct decoded from `plants.json`: `id`, `displayName`, `category`, `heightMeters`, `thumbnail`, `model` |
| `PlantCatalog` | `@Observable` class that loads the manifest once at launch |
| `PlantGridView` | `LazyVGrid` of thumbnails. Loads no 3D at all. |
| `PlantDetailView` | Hosts the `RealityView`, the tap handler and the info card overlay |
| `PlantEntityCache` | Actor that keeps loaded entities by ID and returns `clone(recursive: true)` copies. Holds at most 5 plants, evicts the least recently opened. |
| `StudioLighting` | One directional light for shape plus image-based light from a small bundled HDR for soft fill |

Make the bundle injectable (default `Bundle.main`) so tests can point at the test bundle.

## Runtime behavior

- **Loading:** show the thumbnail PNG as a placeholder until the entity is added, then
  cross-fade. A missing or corrupt USDZ shows the thumbnail with a short error line and never
  crashes.
- **Framing:** use the entity's visual bounds to aim the camera at the plant's vertical middle,
  and back it off in proportion to `heightMeters`. The plant stands upright, base on the floor
  plane, fully in frame on open.
- **Orbit and zoom:** drag orbits, pinch zooms, and the camera never goes inside the plant.
- **Tap:** a tap on the plant toggles the info card. A tap on empty space does nothing.
- **No share or export** action anywhere that exposes a model file (license requirement).
- **Floor:** FABOTANIC exports no ground, so the app draws its own floor.
- **Signposts:** wrap the load call in an `OSSignposter` interval so Instruments can measure
  tap-to-visible time (targets: under 1 s cold, under 0.2 s cached).
- **Accessibility IDs** on the grid cells, the RealityView container and the info card, for UI tests.

## Material fix-up

After `Entity(named:in:)`, walk every `ModelComponent` in the hierarchy. For each
`PhysicallyBasedMaterial`, set `faceCulling = .none` and write the materials back. Leave
`opacityThreshold` as loaded. Then check in the simulator that the placeholder plant's leaf
materials came through with an `opacityThreshold` set (log it once in debug builds). The
converter writes `opacityThreshold` on leaf materials, and it has been verified in the USDZ.
If RealityKit drops it on import, set it from a known value (0.5) for materials whose base
color texture has alpha, and note that in this brief.

## API facts checked on 2026-09-29 (iPhone, not visionOS)

- `RealityView { content in ... }` with `RealityViewCameraContent` is iOS 18+. On iOS the
  default camera is the AR camera, so set `content.camera = .virtual`. The only values are
  `.virtual` and `.spatialTracking`.
- `.realityViewCameraControls(_:)` is iOS 18+. `CameraControls` has `.orbit`, `.pan`, `.tilt`,
  `.dolly` and `.none`. Orbit circles `content.cameraTarget`, so set that to the plant entity.
  - **Not documented:** whether pinch zooms under `.orbit`, and whether it auto-frames.
  - **No API** to clamp zoom distance.
  - **Test first.** If pinch doesn't zoom, or the camera can enter the plant, replace the
    built-in controls with a custom camera: a `PerspectiveCamera` entity placed with
    `look(at:from:upVector:relativeTo:)`, a drag gesture for azimuth and elevation, and a
    `MagnifyGesture` for a radius clamped above the plant's bounding radius. Whether a
    `PerspectiveCamera` coexists with `realityViewCameraControls` is undocumented, so use
    one approach or the other.
- Known bug: changing `cameraTarget` during an orbit drag misbehaves (FB22718768). Set it
  once when the plant is added.
- `SpatialTapGesture().targetedToAnyEntity()` is iOS 18+. `value.entity` can be a child of
  the plant root, so treat any hit as a plant tap. The entity needs a `CollisionComponent`
  plus an `InputTargetComponent`, and the input target is hierarchical. Use
  `generateCollisionShapes(recursive: true)` and put `InputTargetComponent()` on the root.
- `Entity(named:in:)` is `@MainActor`, `async throws`, and iOS 18+. Pass the name without an
  extension. `nil` means the main bundle.
- `visualBounds(relativeTo:)` needs `relativeTo`. Pass `nil` for world space.
- `EnvironmentResource(named:in:)` does not load a bare `.hdr`. It loads a folder named
  `Studio.skybox` containing one equirectangular `.hdr` or `.exr`, added as a folder
  reference and loaded as `"Studio"`. Xcode compiles it; no Reality Composer Pro needed.
  - Fallback: `EnvironmentResource(equirectangular: CGImage, withName:)`.
  - A CC0 1K studio HDRI from Poly Haven is a good source image.
- For lighting only, use `ImageBasedLightComponent(source: .single(env), intensityExponent:)`
  on a light entity plus `ImageBasedLightReceiverComponent(imageBasedLight:)` on the plant.
  `content.environment = .skybox(env)` would also paint the background, so don't use it.
- `DirectionalLight` shines along its -Z axis. Aim it with `look(at:from:upVector:relativeTo:)`.
  It works best when the camera is `.virtual`.
- `ManipulationComponent` is visionOS-only. Don't use it.

## Tests (from the spec)

| Test | Type | Catches |
|---|---|---|
| Manifest integrity | XCTest unit | Entries with no matching USDZ or PNG in the bundle, duplicate IDs, bad heights |
| Every model loads | XCTest unit, async | A USDZ that RealityKit refuses to parse |
| Grid to detail to info card | XCUITest | Navigation and tap wiring. XCUITest can't see inside a RealityView, so tap the view's center by accessibility ID, where the plant sits after framing. |

`scripts/check_plant_assets.py` covers the size and texture gates on Linux CI.

## Performance budgets

| Metric | Target |
|---|---|
| Frame rate while orbiting | 60 fps steady (RealityKit trace in Instruments) |
| Tap on thumbnail to plant visible | Under 1 s cold, under 0.2 s cached (signpost) |
| USDZ per plant | Under 8 MB (CI script) |
| Textures | 1K max per map (CI script) |
| All plant assets in the IPA | Under 150 MB |

## Acceptance criteria

- Every plant in `plants.json` opens from the grid and renders.
- Leaves show cutout gaps with no opaque rectangles or flicker while orbiting.
- No black, untextured or plastic-looking surfaces.
- Plant stands upright, base on the floor plane, fully in frame on open.
- Drag orbits, pinch zooms, and the camera never goes inside the plant.
- Tap on the plant opens the info card; tap on empty space does nothing.
- Missing or corrupt USDZ shows the thumbnail and an error line, with no crash.
- No share or export action exposes a model file anywhere in the app.
- Performance targets met on the oldest test device.
